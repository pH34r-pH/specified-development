# Empty-repository foundation plan

The confirmed public repository was pH34r-pH/specified-development with Apache-2.0 selected. This plan authorized only the minimal central foundation, a reviewable draft PR and exact-head validation. It did not authorize component release, merge, deployment, wiki publication, consumer modification, credential creation or infrastructure charges.

If main remained empty, the deterministic bootstrap leaf made one minimal initial commit containing only README.md and the complete Apache-2.0 LICENSE. That was the sole direct-main exception needed to establish a PR base. If main already existed, it verified the seed/destination/license and preserved existing content rather than forcing/resetting history. It recorded the actual base SHA and disclosure. The bootstrap leaf received one issue identity after the API could create it; no readiness label or owner activation was inferred.

The bounded foundation leaf used a fresh isolated clone/worktree and the exact observed gpt-6-luna binding for the whole attempt, preserving requested reasoning/speed settings. It authored a branch from the seed and added only the review-allowlisted public payload, a stdlib deterministic foundation validator, independent foundation fixtures/tests and CI. The validator enforced manifest/navigation/path/link/inventory basics, source/task/hash/native-edge correspondence, retained paths and explicit pending product status; it did not pretend to implement the complete directory compiler or renderer qualification. Tests covered real malformed independent fixtures, not snapshots of its own output.

It created one issue for that leaf, validated the bootstrap parent as native blocked-by dependency and linked a draft PR. No automatic agent-ready label was added. CI used read-only contents permissions, no secrets/network/inference for validation, Python 3.12, and SHA-pinned first-party actions resolved/verified from official repositories before authoring. The plan deliberately did not guess action commit SHAs. A missing pin blocked draft-PR validation until resolved.

Acceptance required exact PR head SHA and passing CI/check-run evidence at that same SHA plus changed-path inventory, source hashes, allowlist/privacy/license review and actual model/settings/runtime provenance. The worker reported IDs/links and retained local receipts; it did not merge or mark implementation delivered. The existing issue owner controlled claim/closure; no secondary task service was created.
