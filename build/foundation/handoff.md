# Foundation implementation handoff

This repository snapshot published the sanitized design for review. It did not implement the product. Its draft PR commit was a reproducible source packet for the next worker; consume the exact reviewed commit SHA supplied with the PR rather than an unverified branch name. The initial main seed contained only README.md and the complete Apache-2.0 license. No product leaf was marked complete by publishing these documents.

The reusable product used a pinned Spec Kit preset, executable extension and bundle. Canonical `spec/` was also its documentation. Generated compatibility spec.md adapters lived under build/<feature>/; accepted plans, tests, task metadata, issue bindings and evidence remained durable there. Optional site/wiki output was a deterministic one-way source projection. The source contracts, rather than a new model decomposition, defined intended behavior.

Read README.md, spec/index.md, the authority/documents/distribution contracts, build/foundation/plan.md and tests.md, and the assigned record in build/foundation/tasks.md. Scripts can inspect the other accepted metadata and projection; do not feed all 60 records into model context merely to validate or copy them. build/execution-contract.yaml was the sole native task graph. build/native-bindings.json preserved qualified task identities while giving that graph unique local IDs. Source-document dependencies and navigation did not schedule tasks.

The first future model leaf was pH34r-pH/specified-development/foundation/T002, native T002. It used exact observed gpt-6-luna for the whole attempt under fixed-model-v3. Observe availability, runtime, requested/effective reasoning and speed settings, context/output budget and task permissions before claim. Unsupported requirements blocked; no model switch or nonexistent alias substitution was allowed. The bootstrap T001 was a deterministic tools/operator leaf; preserve the already established seed and record actual base evidence instead of reseeding or resetting history.

The bounded foundation implementation authored only its declared stdlib scaffold validator, independent malformed fixtures/tests and read-only, officially SHA-pinned CI. Product compiler/install/projector/renderer behavior stayed for its own later leaves. Complete structural validation, privacy/source inventory/native edge/retention checks and real test fixtures were required; the validator could not pretend to qualify full Markdown/renderers or behavioral regeneration. Fresh model decomposition and a routing service were unnecessary.

Use an isolated branch/worktree at the frozen design commit. If this draft design remained unmerged, a follow-up implementation PR used this design branch as its explicit reviewed base; after merge, use the actual accepted main revision. Preserve concurrent changes and original issue identity. Create only the individually authorized leaf issues with exact markers and native numeric-ID blocked-by dependencies, after complete paginated duplicate/creator/permission checks. Do not publish the remaining 58 product issues, add agent-ready labels or activate an executor as a side effect of scaffold work.

Commit/PR disclosure identifies agent authorship. Keep multiline bodies in files. Acceptance records exact PR head SHA and passing expected check-runs at that same SHA, changed paths, input/native contract hashes, model/runtime/settings/permissions and bounded receipts. A stale passing run or empty status rollup is not evidence. This design-only PR supplied local integrity evidence; it added no executable CI or product tests.

Later component implementation, release, consumer adoption, wiki/site deployment and infrastructure changes follow their own approved gates. Do not merge, deploy, create credentials, modify consumer application repositories, delete retained code/history or incur infrastructure charges through this handoff. A missing behavior or changed authority creates a separate bounded repair task, not a larger model or silent assumption. Observed token-price equivalent uses dated applicable rates; cached tokens remain a subset of input and reasoning a subset of output, and unavailable usage/pricing stays explicit.

Only public manifest-listed source/design content is distributable. Private research, credentials, raw runtime logs and original private review material are excluded. On interruption, re-read exact remote commit/PR state and hashes before resuming; never repeat a seed/create operation merely because a response was lost.
